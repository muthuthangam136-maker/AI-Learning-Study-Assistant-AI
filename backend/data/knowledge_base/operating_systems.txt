# OPERATING SYSTEMS (OS) STUDY GUIDE

## 1. Operating System Fundamentals
An Operating System (OS) is system software that manages computer hardware, software resources, and provides common services for computer programs.
- Dual-Mode Operation: User Mode (restricted instructions, application software runs here) and Kernel Mode (privileged supervisor mode with direct hardware access).
- System Calls: Programmatic method by which a user-level process requests a privileged service from the kernel (e.g., `fork()`, `exec()`, `read()`, `write()`).

## 2. Processes, Threads, and CPU Scheduling
### Processes vs Threads
- Process: An executing program with its own address space, memory segments (Text, Data, Heap, Stack), and Process Control Block (PCB).
- Thread: The smallest dispatchable unit of CPU execution within a process ("lightweight process"). Threads share code segment, data segment, and open file descriptors, but maintain independent thread IDs, program counters, registers, and stacks.

### Process States
- New -> Ready (in memory waiting for CPU) -> Running (executing on CPU) -> Waiting/Blocked (waiting for I/O or event) -> Terminated.

### CPU Scheduling Algorithms
- First-Come, First-Served (FCFS): Non-preemptive, suffers from the Convoy Effect (short jobs stuck behind long jobs).
- Shortest Job First (SJF) / Shortest Remaining Time First (SRTF): Optimal average turnaround/waiting time, but prone to starvation for long processes.
- Priority Scheduling: CPU allocated to highest priority process; mitigated using Aging to prevent starvation.
- Round Robin (RR): Preemptive scheduling using a fixed time quantum. Ideal for interactive time-sharing systems.

## 3. Process Synchronization & Deadlocks
### Inter-Process Communication & Critical Section
- Critical Section: Section of code accessing shared resources that cannot be executed concurrently by multiple processes.
- Requirements: Mutual Exclusion, Progress, Bounded Waiting.
- Synchronization Primitives:
  - Mutex (Mutual Exclusion Lock): Binary locking mechanism. Only the lock owner can unlock it.
  - Semaphore: Integer counter. `wait()` / `P()` decrements counter; `signal()` / `V()` increments counter. Counting semaphore manages finite resource pools.

### Deadlocks
A deadlock is a situation where a set of processes are blocked because each process holds a resource and waits for another resource held by another process in the set.
Four Coffman Conditions (Must all hold simultaneously for deadlock to occur):
1. Mutual Exclusion: At least one resource held in non-shareable mode.
2. Hold and Wait: A process holds at least one resource and is waiting to acquire additional resources.
3. No Preemption: Resources cannot be forcibly taken away; only released voluntarily.
4. Circular Wait: A closed chain of processes exists such that each process holds resources needed by the next.

Deadlock Handling:
- Prevention: Invalidate at least one of the four Coffman conditions.
- Avoidance: Banker's Algorithm dynamically verifies whether granting a resource keeps the system in a "Safe State".
- Detection and Recovery: Periodically construct a Resource Allocation Graph (Wait-For Graph) and abort processes or preempt resources if cycles exist.
- Ignorance: The "Ostrich Algorithm" assumes deadlocks are rare (used by standard OS like Linux and Windows).

## 4. Memory Management & Virtual Memory
- Logical vs Physical Address: Logical address generated by CPU; translated to Physical Address by the Memory Management Unit (MMU) using base and limit registers.
- Paging: Physical memory divided into fixed-size frames; logical address divided into same-sized pages. Eliminates External Fragmentation, though small Internal Fragmentation may occur in the last page.
- Page Table: Maps logical page numbers to physical frame numbers. Translation Lookaside Buffer (TLB) acts as a fast associative hardware cache to speed up address translation.
- Virtual Memory: Allows execution of processes not entirely in physical RAM using Demand Paging.
- Page Fault: Interrupt raised when a process accesses a page not currently mapped in RAM.
- Page Replacement Algorithms:
  - FIFO: Suffers from Belady's Anomaly (more frames can produce more page faults).
  - Optimal (OPT): Replaces page that will not be used for longest time in the future (theoretical benchmark).
  - Least Recently Used (LRU): Replaces page not referenced for the longest period in the past.
  - Clock / Second-Chance Algorithm: Practical approximation of LRU using reference bits.
- Thrashing: Phenomenon where OS spends more time swapping pages in/out of secondary disk storage than executing instructions due to insufficient allocated frames.
